# Bonus Workspace

เว็บแอปบันทึกการขายน้ำแพ็กและถุงขยะ คิดค่าตอบแทน และรายงานตามรอบตัดยอด (หน้าจอภาษาลาว)
ข้อมูลเก็บในเบราว์เซอร์ของเครื่องนี้ (localStorage) ไม่มีเซิร์ฟเวอร์และไม่ส่งข้อมูลออกนอกเครื่อง

## วิธีรัน

ต้องมี Node.js 22.18 ขึ้นไป

```bash
npm install
npm run dev      # เปิด http://localhost:5183
npm test         # ตรวจกติกาคำนวณ
npm run build    # สร้างไฟล์สำหรับใช้งานจริงในโฟลเดอร์ dist
```

หมายเหตุ: ในเครื่องที่สร้างโปรเจกต์นี้ `node_modules` เป็นลิงก์ไปที่
`~/.local/share/bonus-workspace-deps/node_modules` เพื่อไม่ให้ Google Drive ซิงก์ไฟล์หลายพันไฟล์
เครื่องอื่นให้ลบลิงก์แล้วรัน `npm install` ตามปกติ

## โครงไฟล์

- `src/rules.ts` กติกาคำนวณทั้งหมด (ราคาตามขั้น ราคาต่ำสุด ส่วนบริษัท การแบ่งค่าตอบแทน รอบตัดยอด) แยกจากหน้าจอ
- `src/rules.test.ts` เทสต์กติกาตามตารางตัวอย่าง
- `src/store.ts` รูปแบบข้อมูล การบันทึก และการตรวจไฟล์สำรอง JSON (เวอร์ชัน 1)
- `src/pages/` หน้าจอ 7 หน้า · `src/ui.tsx` ชิ้นส่วนที่ใช้ร่วมกัน · `src/app.css` สไตล์

## ส่วนที่ยังรอยืนยันกติกา (หน้าจอแสดง "ລໍຖ້າຕັ້ງຄ່າ")

ดูรายการคำถามในข้อความส่งมอบ จุดที่ต้องแก้เมื่อได้คำตอบอยู่ใน `src/rules.ts` เป็นหลัก

## กติกาที่ผู้ใช้ยืนยันแล้ว (2026-11-25)

1. บิลขายที่ถูกแก้ไขจะกลับไปเป็นสถานะรออนุมัติ แม้เคยรับรองแล้ว
2. ตารางสรุปการเบิกรายคน: ยอด "ขาย" ของแต่ละคนนับจากบิลที่คนนั้นเป็นพนักงานขนส่ง ไม่นับบิลที่ถูกปฏิเสธ และ ยังค้าง = เบิก − ขาย − คืน − เสีย
3. ยอดจ่ายค่าตอบแทนเก็บตามยอดตอนกดทำเครื่องหมายว่าจ่ายแล้ว ถ้ามีบิลรับรองเพิ่มภายหลัง สถานะเป็น "จ่ายบางส่วน" และต้องกดทำเครื่องหมายซ้ำ

4. ยอดคงเหลือรวมตามสินค้าใช้สูตรเดียวกัน: คงเหลือ = เบิก − ขาย − คืน − เสีย (ขาย = ทุกบิลยกเว้นที่ถูกปฏิเสธ) สวิตช์เปิด/ปิดในหน้าตั้งค่าถูกถอดออกแล้ว

## ใช้หลายเครื่อง (โหมดข้อมูลกลาง)

แอปมีสองโหมด เลือกจากค่า `VITE_API_URL` ตอน build

- **โหมดในเครื่อง** (`npm run dev`): ไม่มีค่า `VITE_API_URL` ข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้น ไม่ต้องใส่ PIN
- **โหมดข้อมูลกลาง** (`npm run build` อ่าน `.env.production`): ทุกเครื่องใช้ข้อมูลชุดเดียว ต้องใส่ PIN 8 หลัก

ส่วนประกอบของโหมดข้อมูลกลาง

- `supabase/migration.sql` ตาราง `bonus_state` (ข้อมูล) `bonus_history` (สำเนาวันละชุด) `bonus_pins` `bonus_fails` ในโปรเจกต์ Supabase vari-trucks เปิด row level security และไม่มี policy จึงอ่านเขียนได้ผ่านฟังก์ชันเท่านั้น
- `supabase/functions/bonus-workspace/` ฟังก์ชันกลาง `core.ts` คือกติกา (PIN สิทธิ์ การกันบันทึกทับกัน) `index.ts` คือส่วนต่อกับ Supabase
- `src/sync.ts` `src/merge.ts` และ `Shared` ใน `src/App.tsx` คือฝั่งแอป: ดึงข้อมูลทุก 20 วินาทีและเมื่อกลับมาที่แท็บ บันทึกหลังแก้ 0.5 วินาที ถ้าสองเครื่องบันทึกชนกันจะรวมข้อมูลให้ ไม่ทับกัน

สิทธิ์สองระดับ (ตรวจที่ฟังก์ชันกลาง ไม่ใช่แค่ซ่อนปุ่ม)

- **พนักงาน:** บันทึก แก้ไข ลบ บิลที่ยังรออนุมัติ เงินสด สต็อก บิลยกเลิก และรายชื่อลูกค้า
- **ผู้จัดการ:** ทุกอย่างของพนักงาน และรับรอง/ปฏิเสธบิล แก้บิลที่ตัดสินแล้ว กติกา ราคาสินค้า รายชื่อพนักงานและบทบาท ทำเครื่องหมายจ่ายค่าตอบแทน นำเข้า JSON และเปลี่ยน PIN

ทดสอบโหมดข้อมูลกลางในเครื่องโดยไม่แตะระบบจริง

```bash
node scripts/mock-api.ts
VITE_API_URL=http://localhost:5184 npx vite --port 5185
```

PIN ทดสอบอยู่ใน `scripts/mock-api.ts` ใช้ได้กับเซิร์ฟเวอร์จำลองเท่านั้น
